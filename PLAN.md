# План: Telegram-бот «AI-ассистент продаж» (тестовое задание)

## Задача
Собрать с помощью ИИ скрипт/сервис, который:
1. принимает обращение клиента (через Telegram-бота),
2. сверяется с короткой базой знаний (БЗ),
3. выдаёт **два блока**: вежливый ответ клиенту + подсказку по допродажам для менеджера
   (с учётом контекста диалога менеджера в AmoCRM).

## Согласованные решения
| Вопрос | Решение |
|---|---|
| AmoCRM | Симуляция контекста: менеджер вставляет фрагмент диалога из AmoCRM в сообщение бота (через разделитель `---` или команду `/crm`). Без API-ключей. |
| Содержимое БЗ | Демо-БЗ (придумываю, позже заменяется на реальный FAQ). |
| Поиск по БЗ | Весь текст БЗ кладётся в системный промпт (БЗ короткая). |
| Режим бота | Long polling (`python main.py` локально, без домена). |
| История | Stateless — без сохранения переписки. |
| Выдача | Оба блока сразу в одном сообщении с разметкой. |

## Стек
- Python 3.11
- `python-telegram-bot` — Telegram, long polling
- `httpx` — async-клиент к Ollama API (`http://localhost:11434`)
- Модель: `qwen2.5:3b` (уже в `simple_ollama` / ollama/ollama)
- `python-dotenv` — хранение секретов (токен НЕ в коде)
- Ollama `format: json` + `temperature: 0.2` — стабильный JSON-вывод


## Формат вывода LLM
Строгий JSON:
```json
{
  "client_response": "вежливый ответ клиенту",
  "manager_hint": "подсказка по допродажам для менеджера",
  "kb_section": "раздел БЗ, который использовался"
}
```
При невалидном JSON — fallback: текст разрезается по маркеру, либо возвращается ошибкаriendly-сообщение.

## Логика работы
1. Пользователь отправляет обращение.
2. Если менеджер приложил контекст диалога из AmoCRM (блок до/после `---` или команда `/crm <текст>`) — он передаётся в промпт отдельным полем.
3. В промпт подставляется: роль (вежливый саппорт + sales-ассистент), **вся БЗ**, инструкция выдать JSON.
4. Запрос в Ollama → парсинг JSON → ответ в Telegram двумя блоками:
   - 💬 **Ответ клиенту**
   - 🎯 **Подсказка менеджеру** (что предложить/как закрыть сделку)
   - 📚 раздел БЗ
5. Команды: `/start`, `/help`, `/kb` (показать БЗ), `/crm` (как передать контекст AmoCRM).

## Шаги реализации
1. **Каркас** — `requirements.txt`, `.env.example`, `.gitignore`, `config.py`
2. **Ollama-клиент** — `ollama_client.py` + smoke-проверка связи
3. **БЗ и промпт** — `knowledge_base.md` (доставка, оплата, возврат, гарантия, допродажи) + `prompts.py`
4. **Бот** — `handlers.py` + `main.py`, polling, разметка двух блоков
5. **Устойчивость** — ретраи, таймауты, обработка падения Ollama и невалидного JSON
6. **Проверка** — smoke-тест парсера/промпта, живой прогон бота, `README.md`

## Риски и mitigation
- `qwen2.5:3b` шумит на русском → `format: json`, `temperature: 0.2`; при необходимости докачать `qwen2.5:7b`
- Ollama недоступен → дружелюбное сообщение об ошибке в бот
- ⚠️ Токен бота засветился в чате → после тестового перевыпустить через @BotFather, хранить только в `.env`
